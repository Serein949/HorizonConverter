# 转换格式对照表（文件格式 + 像素格式）

Aerofly 的文件可以分两层来看：

1. **容器格式**——文件本身是什么（`.ttx`、`.ttc`、`.tsb`、`.tmb` …），转换器按扩展名判断该用哪个模式；
2. **像素格式**——贴图容器**内部**用什么方式存像素（DXT1、DXT5、ETC2、R8、ASTC …）。

两层是独立的：同一个 `.ttx` 里既可能装 DXT1，也可能装 ASTC。

---

## 一、容器格式

| 扩展名 | 是什么 | 转换器支持 | 关键点 |
|---|---|---|---|
| `.ttx` | 飞机/机场**贴图**容器 | PNG ⇄ TTX | 桌面版用 DXT 系；内含完整 mip 链；整个 payload 用 LZHAM 压缩 |
| `.ttc` | **场景/地形贴图**切片 | PNG ⇄ TTC | 默认上下翻转；游戏自带的 `map_*.ttc` 是未公开变体，读不了（工具会明确报错） |
| `.tsb` | **声音**容器 | WAV ⇄ TSB | 也接受 `.mp3` / `.ogg` / `.flac` 直接转 WAV |
| `.tmb` | **几何/模型**（TM 系容器） | TM → 文本树 | 只做导出查看（`.tmb.txt`），不做写回 |
| `.tmd` / `.tms` / `.tmi` | 其它 TM 系容器 | TM → 文本树 | 同上，用于分析格式 |
| `.tme` | 打包容器 | ZIP ⇄ TME | 与 zip 互换 |
| `.tsc` / `.tsl` / `.toc` / `.wad` | 地景描述 / 摆放 / 索引 / 波纹 | 只解压不转换 | 转换器只负责识别与解出内部结构 |

> 命令行不加 `-m` 时按扩展名自动选模式，例如 `AeroflyConv livery.ttx` 等于 `-m ttx2png`，
> `AeroflyConv livery.png -m png2ttx` 才是反向。

### 为什么贴图要压一层 LZHAM

`.ttx` 里的像素数据不是裸块数据，外面还套了一层 LZHAM 压缩流。同一张 2048² DXT1 贴图：

- 裸块数据（含 mip 链）：**2,796,528 B**
- 套上 LZHAM 后写进文件：约 **324,706 B**（8.61×）

所以文件大小 ≈ 压缩后的体积，而不是上表里那些"原始体积"。1.21 之前的版本写的是
"不压缩的 raw block"，文件会明显偏大——这就是那次修复的内容。

## 二、像素格式（贴图内部）

块压缩格式把图片切成 4×4 像素小块，每块压成固定字节数：体积小、GPU 采样快，但**有损**。
下表的体积是"含完整 mip 链"的原始体积（未 LZHAM 压缩）。

| 格式（CLI 写法） | 每块 | 每像素 | 2048² 全 mip | 透明 | 用在哪 |
|---|---|---|---|---|---|
| `dxt1` | 8 B | 4 bit | 2.68 MB | 只有 1 位（开/关） | 机身、机翼、地景——桌面版主力 |
| `dxt5` | 16 B | 8 bit | 5.33 MB | 8 级 alpha 渐变 | 舷窗、玻璃、涂装镂空 |
| `etc2` | 8 B | 4 bit | 2.68 MB | 无 | 手机（GLES 3），桌面版读不了 |
| `type_rgba_etc2` | 16 B | 8 bit | 5.33 MB | EAC alpha | 手机的透明贴图 |
| `astc6x6` / `astc5x5` | 16 B | 0.44 / 0.64 B | 2.37 / 3.41 MB | 由块大小决定 | 新版手机；桌面版不读 |
| `type_r`（R8） | — | 8 bit | 5.33 MB | 单通道 | 遮罩、金属度、粗糙度、自发光 |
| `type_rgba` | — | 32 bit | 21.3 MB | 完整 | 要求零画质损失时用 |
| BC5（`type_rg_*`） | 16 B | 8 bit | 5.33 MB | 双通道 | 法线贴图（只存 RG，Z 由 GPU 重建） |

几条容易踩的规律：

- **带 alpha 的格式体积翻倍**：DXT5 就是"DXT1 颜色块 + 8 字节 alpha 块"。
- **不压缩的格式反而更大**：R8 每像素 1 字节，比 DXT1 的 0.5 字节还占地方。
- **桌面版只认 DXT**：把贴图写成 ETC2/ASTC 后，PC 版 Aerofly 看不到——那是给手机版的。
- **PSNR 40 dB 以上基本肉眼无差**；DXT1 实测 46.8 dB，ETC2 41.5 dB，ASTC 真实贴图 41–51 dB。

详细原理、画质实测和逐格式优缺点见 [`formats.md`](formats.md)。

## 三、怎么选（一分钟版）

| 你要做的事 | 用哪个 |
|---|---|
| 改飞机涂装、机场贴图（PC 版） | `ttx ⇄ png`，格式 `dxt1`（不透明）或 `dxt5`（要透明） |
| 改手机版贴图 | `astc5x5` / `astc6x6`，老设备用 `etc2` |
| 提取别人的贴图看长什么样 | `ttx → png`，不用管格式，转换器自动识别 |
| 改声音 | `tsb ⇄ wav` |
| 想研究模型结构 | `tmb → tmb.txt` |
| 只想知道文件里有什么 | `--info` |

```powershell
AeroflyConv livery.ttx                       # 贴图导出成 PNG
AeroflyConv livery.png -m png2ttx -f dxt5    # 带透明地写回
AeroflyConv engine.tsb                       # 声音导出成 WAV
AeroflyConv airport.tmb                      # 模型导出成文本树
```

## 四、常见误区

**「TTX 和 TTC 不是都是贴图吗？」**
都是贴图，但用途不同：`.ttx` 给飞机/机场用，`.ttc` 给地形切片用，翻转与格式约定也不一样，
所以转换器把两者做成了两个模式。

**「我 2048² 的贴图为什么只有 300 KB？」**
因为文件里是 LZHAM 压缩过的；裸块数据其实有 2.68 MB。看文件大小判断不了画质。

**「ASTC 数字最小，是不是最划算？」**
压缩比确实好，但编码很慢（2048² 约 30 s，DXT1 只要 0.6 s），而且只有手机版读。PC 用不上。

**「R8 是不是低清版？」**
不是。R8 是**无损单通道**，只是没有颜色；它比 DXT1 还大，因为完全不压缩。
